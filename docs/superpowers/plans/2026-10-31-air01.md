# Air 01 Rust Tool Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Build and install a Rust CLI, then TUI, and verify the requested Ctrl/Fn swap on device 3013.
**Architecture:** Shared typed protocol and operations library; Linux HID transport; CLI and TUI clients. Every mutation is backed up, paced, scoped, and verified with a fake transport and actual hardware.
**Tech Stack:** Rust, hidapi (linux-native-basic-udev), clap, serde, ratatui/crossterm, Nix.
**Spec:** docs/superpowers/specs/2026-10-31-air01-design.md

## Global Constraints

- Wired writes only; only device 3013 and hardware-confirmed Gen2 writes.
- No firmware/reset/Hall-effect commands. Preserve unknown key entries.
- CLI first, then TUI. GPL-3.0-or-later; local repository, no publishing.
- Backup before writes; bounded I/O; exclusive process lock; read-back and recovery.
- All four base profiles receive the requested swap during live validation.

## Review Focus

- An unsupported identity/protocol must never receive a write (task 2/3 tests).
- A disconnect or failed read-back must report partial failure and attempt verified recovery (task 3).
- A malformed or foreign snapshot must fail before writes (task 2/3).
- Remapping Fn must keep a usable Fn through intermediate states (task 3).
- No-op operations must not commit to flash; active profile must not silently change (task 3).
