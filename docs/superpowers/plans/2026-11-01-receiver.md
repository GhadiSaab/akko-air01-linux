# Receiver configuration implementation plan

> **For agentic workers:** Use superpowers:executing-plans inline.

**Goal:** Verified2.4GHz Air01 configuration in CLI/TUI before publishing.
**Architecture:** Generic raw feature report relay beneath Wire; explicit receiver
link metadata and narrow configuration capabilities on identified Board.
**Stack:** Existing Rust/hidapi/Ratatui; no new dependencies.
**Spec:** docs/superpowers/specs/2026-11-01-receiver-design.md

## Constraints / review focus
Only device3013 Gen2, USB3151:5002 or5006. Preserve settings/active profile. Never
resend uncertain writes. Active-profile remaps only through receiver. Animation
uploads remain cable-only. Handle receiver asleep/busy/unpaired/short/stale replies.

- [ ] Relay: failing scripted raw-I/O tests; receiver.rs status/parser/exchange;
  HidWire worker routes exchanges by link; retain poisoning and process lock.
- [ ] Discovery/capabilities: default receiver marker on Wire, Board capability,
  known-interface selection/cable preference, CLI/TUI link labels, narrow guards,
  tests for wireless active remaps/lighting/profile and blocked inactive/animation.
- [ ] Hardware: exact original backup, reversible operation roundtrips, final
  equality checks; fresh review, fmt/test/Clippy/Nix, installed TUI and docs.
- [ ] Publish audited source using gh CLI to a public GitHub repository, with
  accurate support limits/license/install instructions and CI; verify remote.
