# Receiver configuration implementation plan

> **For agentic workers:** Use superpowers:executing-plans inline.

**Goal:** Verified2.4GHz Air01 configuration in CLI/TUI before publishing.
**Architecture:** Generic raw feature report relay beneath Wire; explicit receiver
link metadata and narrow configuration capabilities on identified Board.
**Stack:** Existing Rust/hidapi/Ratatui; no new dependencies.
**Spec:** docs/superpowers/specs/2026-11-01-receiver-design.md

## Constraints / review focus
Only device3013 Gen2, USB3151:5002 or5006. Preserve settings/active profile. Never
resend uncertain writes. Active-profile remaps only through receiver. Animation
uploads remain cable-only. Handle receiver asleep/busy/unpaired/short/stale replies.

- [x] Relay: failing scripted raw-I/O tests; receiver.rs status/parser/exchange;
  HidWire worker routes exchanges by link; retain poisoning and process lock.
- [x] Discovery/capabilities: default receiver marker on Wire, Board capability,
  known-interface selection/cable preference, CLI/TUI link labels, narrow guards,
  tests for wireless active remaps/lighting/profile and blocked inactive/animation.
- [ ] Hardware: exact original backup, reversible operation roundtrips, final
  equality checks; fresh review, fmt/test/Clippy/Nix, installed TUI and docs.
- [ ] Publish audited source using gh CLI to a public GitHub repository, with
  accurate support limits/license/install instructions and CI; verify remote.

## Findings / review
- Real receiver status tail retained109 from an earlier report; fixed false RF
  boot detection. A ready reply is consumed even if online flag went idle.
- Wait100ms for receiver control GETs,200ms quiet time per logical exchange,
  cache selected keyboard target, bounded read-only retry after missing/busy read.
  Never resend a write. Worker15s covers the maximum bounded exchange; USB3s.
- User confirms responsive typing with probes stopped, and accepts latency while
  actively using/configuring through the TUI. No idle polling is implemented.
- Complete receiver backup equals previous wired snapshot. Temporary lighting,
  base, WinFn, MacFn and profile changes all verified/restored. Final full equality
  checks passed, including exact lighting parameters.
- Fresh reviewer found rollback could target a now-inactive profile. Guard moved
  into write_verify, covering both forward and reverse writes; regression verifies
  INCOMPLETE rather than sending an inactive-profile recovery write.
- 96 tests and Clippy pass. TUI harness corrected for native-terminal cursor
  positioning that splits text across ANSI writes; its child group is cleaned up.

- Read-only probing tolerates a transient offline status, while writes still reject
  it. Added regressions for both rules. Trace harness found a false-negative screen
  match on native rendering; corrected markers and owned child-process cleanup.
